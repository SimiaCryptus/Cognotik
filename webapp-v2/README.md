# Chat client — v2 (modular ES6)

    Implementation of `../webapp/reverse-spec.md`. No React, no Redux, no
    styled-components: Prism, Mermaid and MathJax all operate directly on the DOM, so
    the DOM *is* the state for rendered content.

    ## Run

    ```bash
    npm install
    npm run dev        # vite dev server
    npm run build      # -> build/ (base: './', safe under any path prefix)
    ./build.sh         # build + stage into ../webui/src/main/resources
    ```

    ## §20 defects — resolution

    1. **lastMessageTime** — high-water mark tracked in `MessageStore`
       (`version` when it is plausibly epoch-ms, else receipt time); `0` on cold start.
    2. **Two reconnect loops** — only `core/transport.js` schedules reconnects.
    3. **Double renderer init** — `initMermaid()` guards with a module flag and is the
       only caller of `mermaid.initialize`; `Prism.manual = true` lives in
       `prism-manual.js`, imported before any plugin; highlighting is scoped and
       `IntersectionObserver`-driven, never `Prism.highlightAll()`.
    4. **Sanitisation theatre** — removed. Server HTML is **trusted** (it is generated by
       the same trust domain that serves the page, and it must be able to emit the
       control/tab markup in §7/§8). DOMPurify is no longer a dependency. If a future
       deployment needs untrusted HTML, re-introduce sanitisation in
       `render/message-list.js` only, preserving `$…$`, `$$…$$`, `\(…\)`, `\[…\]`.
    5. **Modal under-processing** — modal HTML emits `MODAL_CONTENT_READY`; the pipeline
       runs scoped to the modal root (tabs, collapsibles, Prism, Mermaid, MathJax).
    6. **Unreachable UI handlers** — `installModalTriggers()` (`[data-modal]`) is
       installed exactly once; message actions are handled once, by delegation on the
       message list (§7).
    7. **isArchive** — one definition, `config/archive.js`.
    8. **Type derived twice / ids mangled** — `deriveType()` runs only in the store; ids
       are never rewritten, so version-based upsert and `z*` resolution both work.
    9. **Shadow message state** — gone; the store is the only copy.
    10. **isValidTheme stale** — theming deferred (§19.1); no silent downgrade exists here.
    11. **O(all messages) re-expansion** — `hostsByRef` / `refsByHost` reverse index; a
        `z*` update dirties only its hosts.
    12. **Collapsible expando flag** — `dataset.collapsibleBound`.
    13. **Stale test asserting "learn react"** — not ported; replacement suite should be
        anchored on the §18 conformance checklist.

    ## Intentional divergences

    * **Buffer flush on close.** §3.6 says buffers are *cleared* on close; we flush any
      already-decoded messages first so a close mid-replay cannot lose content, then
      clear buffers and timers.
    * **`transport.send()` returns a Promise** that resolves when the frame is written to
      the socket. This is what makes "clear the composer only after the send resolves"
      and "drafts survive reconnects" both true. The composer races it against a 10 s
      timeout so a long outage cannot wedge the UI (the draft is kept).
    * **Auto-scroll policy** (§19.3.5, previously unspecified): stick to the bottom while
      the user is within 40 px of it; stop as soon as they scroll up.
    * **Reply-input drafts are preserved** across a message's HTML being replaced.
    * `derivePath()` follows §3.1 literally (first path segment). If the app is ever
      served from a file-like path (`/index.html`), pass an explicit `path` in the
      transport config.

    ## Deferred (§19)

    Themes (§19.1), menubar/dropdowns (§19.2) and UI polish (§19.3) are **not** ported.
    Seams left for them:

    * `config/app-config.js#applyMenubarConfig` already implements the legacy
      `showMenubar === false` DOM contract.
    * `render/prism.js` exports `highlightWithin` / `highlightAllUnder`; a theme module
      only needs to swap the Prism stylesheet and clear `.prismjs-processed`.
    * `styles/base.css` declares the `--theme-*` / `--font-*` / `--spacing-*` variables it
      consumes with neutral fallbacks, so a theme module can override them on `:root`.
    * `ui/modal.js` exports `openModal` / `getModalUrl` for menu items to call.
    * `render/verbose.js` exports `setVerbose` / `toggleVerbose` for a menu item.
