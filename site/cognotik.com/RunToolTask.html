Task Execution Lifecycle

  • 1. Context Loading Retrieves prior code context from the execution state to provide environment awareness.
  • 2. Tool Resolution Looks up the tool name in UserSettings. Resolves the absolute path to the executable using configured providers.
  • 3. Validation Ensures the executable exists and validates the workingDir relative to the project root.
  • 4. Interaction Gate If autoFix is false, the task enters a pending state, rendering a "Run Tool" button for manual approval.
  • 5. Process Execution Spawns a system process via ProcessBuilder. Merges stdout and stderr for unified logging.
  • 6. Reporting & Cleanup Captures exit codes and output. Writes results to the task transcript and updates the Session UI.

Kotlin Boilerplate

Example of invoking RunToolTask using the UnifiedHarness in an embedded environment:


import com.simiacryptus.cognotik.plan.tools.run.RunToolTaskExecutionConfigData
import com.simiacryptus.cognotik.plan.tools.run.RunToolTask.Companion.RunTool

// 1. Define the Job settings
val config = RunToolTaskExecutionConfigData(
    tool = "python", // Must match a configured tool executable
    args = listOf("scripts/verify_data.py", "--verbose"),
    workingDir = ".",
    task_description = "Verify data integrity using python script"
)

// 2. Execute via Harness
harness.runTask(
    taskType = RunTool,
    typeConfig = RunToolTask.RunToolTaskTypeConfig(),
    executionConfig = config,
    workspace = File("./my-project"),
    autoFix = true // Set to true for headless/CI execution
)
