Runtime Parameters (ExecutionConfig)

Field Type Description
planning_goal * String The high-level objective for the sub-planner to decompose and execute.
context List<String> Supplemental information, logs, or constraints provided to the sub-planner.
task_description String Alternative to planning_goal; used if the goal is not explicitly provided.

Task Capabilities

The SubPlanTask is unique because it acts as a container. It inherits the capabilities of the TaskOrchestrator but can be restricted to specific sub-tasks via its Type Configuration.

Type Configuration (Static Settings)

Field Type Description
cognitiveSettings CognitiveModeConfig Overrides the global cognitive strategy for this sub-plan (e.g., Adaptive).
taskSettings Map<String, TaskTypeConfig> Defines the specific task types allowed to be spawned within this sub-plan.
purpose String Internal documentation for why this specific sub-plan configuration exists.
summaryPrompt String The template used by the LLM to aggregate results into the final summary.

Lifecycle Process

  1. Initialization: Validates the goal and prepares the recursive environment with inherited or overridden settings.
  2. Planning: The selected Cognitive Mode analyzes the goal and generates a sequence of sub-tasks.
  3. Execution: Sub-tasks are executed within an isolated session context, reporting results back to the parent orchestrator.
  4. Aggregation: Results are collected and processed by the summaryPrompt to generate a final synthesis.

Kotlin Boilerplate

OrchestrationConfig.kt
val subPlanConfig = SubPlanTask.SubPlanTaskTypeConfig(
    purpose = "Specialized UI Refactoring",
    cognitiveSettings = CognitiveModeType.Adaptive.newSettings(),
    taskSettings = mutableMapOf(
        "FileModification" to FileModificationTask.TypeConfig(),
        "WebSearch" to WebSearchTask.TypeConfig()
    )
)

// Register in your orchestration config
orchestrationConfig.taskSettings[SubPlanTask.SubPlan.name] = subPlanConfig
