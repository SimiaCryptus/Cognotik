### 1. Recommended Experiments

    *   If connections are **Active**: Confirms $H_1$ due to slow queries or high volume.

#### Experiment B: Heap Usage vs. Connection Pool Correlation
*   **Action:** Plot JVM/Node.js Heap Memory usage against DB Connection Pool usage over the 5-minute window leading up to the performance degradation.
*   **Rationale:** If $H_2$ (Memory Leak) is the cause, we should see a monotonic increase in heap memory that precedes or correlates perfectly with the latency.
*   **Diagnostic Value:** 
    *   High correlation with heap growth = $H_2$.
    *   Flat heap with rising connection count = $H_1$.

#### Experiment C: The "Pool Expansion" Stress Test
*   **Action:** Temporarily double the max connection pool size on a single canary node.
*   **Rationale:** This tests the "Time-to-Failure."
*   **Diagnostic Value:**
    *   If the "Restart Relief" window extends from 5 minutes to 10 minutes, it confirms a **leak** (either memory or connection).
    *   If the 95% utilization remains but latency improves, the pool was simply **undersized** for the load.
