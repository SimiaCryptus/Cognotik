# Cognotik 2.1.19 — AI That Works From Anywhere

Since 2.1.18, Cognotik has made a major architectural leap: core capabilities have been
split into standalone, independently-consumable libraries, the chat frontend has been
rewritten from scratch, and AI-powered development is now available directly from your
terminal and browser — no IDE required.

---

## New: Cognotik Chat Client v2 (`webapp-v2`)

The chat UI has been fully rewritten as a dependency-light, framework-free ES6 module
application — no virtual DOM, no bundled framework, no surprises. Found in the new
[`webapp-v2`](../../webapp-v2/src) module, it ships via [`build.sh`](../../webapp-v2/build.sh)
into the `webui` resources.

**Clean layered architecture.** A strict dependency rule keeps the layers honest:
[`core/`](../../webapp-v2/src/core) (transport and state) never imports
[`render/`](../../webapp-v2/src/render) or [`ui/`](../../webapp-v2/src/ui); cross-cutting
events travel upward only through a central [`bus.js`](../../webapp-v2/src/core/bus.js).
The full module layout:

```
core/     — WebSocket transport, session identity, message store, protocol encode/decode
render/   — DOM reconciliation, tabs, collapsibles, Prism, Mermaid, MathJax
ui/       — shell, composer with markdown toolbar, modal host
config/   — environment, theming, app-config, archive mode
```

**Robust WebSocket transport.** A single reconnect authority
([`transport.js`](../../webapp-v2/src/core/transport.js)) handles exponential backoff
(1s → 30s, 5 attempts), a 10s connect timeout, 30s heartbeat, a send queue that resolves
promises only when frames are actually written, cold-start replay buffering, and
steady-state aggregation drained in chunks of 10.

**Token-only theming with zero flash.** Themes are pure CSS custom property sets
(`--theme-*`) applied before any renderer initialises or content is mounted. Light and dark
are built in; `auto` tracks `prefers-color-scheme` live. Adding a new theme is two steps: a
CSS block and one registration line. The theme API is also available from the browser
console via `__cognotik.setTheme('dark')`.

**Archive mode.** Enabled by `<html data-archive>` or a `/archive/` path — messages are
hydrated from an embedded JSON payload, socket and appInfo calls are skipped, and
interactive affordances are disabled. Themes still apply.

**Built-in diagnostics.** `__cognotik.diagnostics()` gives a counter snapshot for every
subsystem; `__cognotik.transport.stats()` exposes socket state, queue depth, and uptime.
Global `error` / `unhandledrejection` traps show a fatal-error panel instead of a blank page.

## New Standalone Library: `cognotik:text`

The patch processing and response parsing engine that powers every code edit in Cognotik has
been extracted into its own publishable library — the
[`text` module](../../text/src/main/kotlin/com/simiacryptus/cognotik) — with **no dependency
on any LLM client or platform runtime**. It operates purely on strings.

This is the foundation that takes raw, unpredictable model output and turns it into
deterministic, validated file mutations.

**Parse any model response format.** `PatchParser` understands three overlapping
conventions — explicit `<<<DIFF>>>` / `<<<FILE>>>` markers, markdown `#`-header attribution,
and bare fenced blocks — and normalizes filenames with a fixed-point cleaner that strips the
prefixes models commonly hallucinate (`File:`, `Path:`, `Modified:`, etc.).

**Apply patches with real tolerance for model sloppiness.** Five interchangeable engines
cover every scenario:

| Engine | Best for |
|---|---|
| `FuzzyPatchMatcher` | General purpose — line linking + Levenshtein with snippet fallback |
| `ThermodynamicPatchMatcher` | Small, noisy hunks — Needleman-Wunsch DP with a binding-energy model |
| `PythonPatcher` | Python and YAML — indentation-preserving normalization |
| `FullReplacementProcessor` | Large rewrites — whole-file replacement, zero application risk |
| `DataMergeProcessor` | Config files — structured deep merge for JSON, YAML, XML, TOML, `.properties` |

**Validate after every hunk.** The `GrammarValidator` registry applies the right checker per
file type — ANTLR-based `KotlinGrammarValidator` for `.kt` files, `ParenMatchingValidator`
for everything else — and crucially, *subtracts pre-existing errors* so a bad patch in an
already-broken file is still correctly detected. The registry is open for extension.

**Embed it in three lines:**

```kotlin
val processor = PatchProcessors.Fuzzy
val prompt = processor.patchFormatPrompt   // feed this to your model
val result = processor.apply(original, modelResponse, filename = "src/Main.kt")
if (result.isValid) file.writeText(result.newCode)
```

The library ships sources, javadoc, and optional signing via
`./gradlew publishToMavenLocal`, with Jackson, ANTLR, and Groovy as optional dependencies
that can be excluded if you only need the core patch engines.

## Brand-New: The Cognotik CLI

The headline feature of 2.1.19 is a full-featured command-line toolkit distributed as a
standalone fat JAR (now automatically built and uploaded as a release artifact by CI).
Three powerful tools ship out of the box.

### `autofix` — Self-healing builds

Wrap any shell command and let Cognotik fix it. The agent runs your command, reads the
errors, patches the source, and retries autonomously until the build is green — or until you
step in to review.

```sh
cognotik autofix -- ./gradlew build
cognotik autofix "npm test" --no-auto-fix   # propose patches, you approve
```

### `docops` — AI document generation from the command line

Drive Cognotik's declarative DocProcessor engine from a terminal. Plan what will happen
without touching a file, then execute with concurrency control and a live browser monitor —
or run fully headless in CI.

```sh
cognotik docops plan                           # what would happen?
cognotik docops run docs/api.md --var MODULE=billing
cognotik docops run --mode ForceUpdate -c 8 --open
```

### `fileserver` — An AI-enhanced local file server

Serve any directory with a smart file browser that brings Cognotik's agentic capabilities
directly to the web UI: per-file *Modify* links (the IDE's `ModifyFilesAction`, now in your
browser), per-document *Plan / Run* buttons for markdown files, an *AutoFix* toolbar, live
task-output polling, optional git integration, and interactive terminal sessions.

```sh
cognotik fileserver --port 8081 ./my-project
cognotik fileserver --secure ./my-project     # read-only, no terminal, locked down
```

It also exposes a clean REST API so your own tools can invoke agentic workflows
programmatically:

```
POST /.fsapi/v1/docops?command=run&path=docs/api.md
POST /.fsapi/v1/autofix?cmd=./gradlew%20build
POST /.fsapi/v1/modify?path=src/Foo.kt
GET  /.fsapi/v1/tasks
```

## Expanded Language Intelligence (ANTLR Grammar Suite)

The [`antlr` module](../../antlr/src/main/antlr) now covers **Python 3.13, Rust, TypeScript,
ECMAScript (ES5), HTML, CSS3, Java 20, JSON5, and Kotlin** — giving the `text` library's
`KotlinGrammarValidator` (and future per-language validators) precise structural coverage of
virtually every mainstream language. Code edits are grammar-aware, not just text-based.

## Under the Hood

- All three CLI tools are **one-shot processes** with ephemeral Jetty servers: they start a
  browser monitor only when there is work to watch, and always clean up on exit (Ctrl-C
  included). No daemons, no PID files, no port conflicts.
- **Planning is always pure**: `docops plan` never mutates your workspace and never starts a
  server.
- **Path jailing**: all paths from CLI args or HTTP requests are canonicalized against the
  configured root before any file operation.
- The CLI fat JAR is built and uploaded as a release artifact automatically by CI — download
  it and run it anywhere Java is available.
