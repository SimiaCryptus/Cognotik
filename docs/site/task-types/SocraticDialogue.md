# SocraticDialogue

**Explore ideas through structured, adversarial-collaborative Socratic questioning between two LLM agents.**

`Side-Effect Safe` · `Reasoning` · `No Vision Required`

---

## Reality Check

**Input configuration**

```json
{
  "task_type": "SocraticDialogue",
  "initial_question": "Is a distributed system's 'consistency' guarantee meaningful without a defined failure model?",
  "related_files": ["src/main/kotlin/consensus/*.kt"],
  "max_depth": 5,
  "challenge_assumptions": true,
  "domain_constraints": ["distributed systems", "CAP theorem"],
  "task_dependencies": []
}
```

**Rendered output (UI)**

The task renders a `TabbedDisplay` with one tab per exchange plus `Overview`, `Context` (if input files provided),
and `Synthesis` tabs:

- **Overview tab:** live-updating markdown log — initial question, config summary, a checklist of completed
  exchanges with per-exchange timing, and a final completion banner with total time and character count.
- **Exchange N tabs:** each shows the question posed, a "Generating response…" placeholder that resolves into the
  responder's full answer, then (if not the last exchange) the next question generated by the questioner agent.
- **Context tab:** raw contents of any glob-matched `related_files`, concatenated as fenced code blocks per file.
- **Synthesis tab:** a final markdown write-up synthesizing insights, challenged/confirmed assumptions,
  contradictions, and open questions.
- **Downloadable transcript file** (`.md`) written incrementally via `newUserFileStream`, containing the full
  dialogue, synthesis, and timing footer.
- **Returned result string** (`resultFn`) is a *concise* version — only the first and last exchange are included in
  full, plus the synthesis — to control payload size passed to downstream tasks.

## Documentation

### Configuration

| Field Name             | Required/Optional | Type            | Description                                                                 |
|-------------------------|--------------------|------------------|-------------------------------------------------------------------------------|
| `initial_question`      | Required           | `String`         | The initial question or hypothesis to explore.                              |
| `related_files`         | Optional           | `List<String>`   | Glob patterns for input files to provide context for the dialogue.          |
| `max_depth`             | Optional (default 5) | `Int`          | Maximum dialogue depth (number of question-answer exchanges). Clamped 1–20. |
| `challenge_assumptions` | Optional (default true) | `Boolean`   | Whether to actively challenge assumptions at each level.                    |
| `domain_constraints`    | Optional           | `List<String>`   | Topics or domains to constrain the dialogue.                                |
| `task_dependencies`     | Optional           | `List<String>`   | IDs of prerequisite tasks (inherited from `TaskExecutionConfig`).            |

### Dependencies

No hard dependencies on other task types. `SocraticDialogueTask` is self-contained but participates in the standard
`task_dependencies` orchestration wiring like any other `AbstractTask`, and can consume prior task output via
`getPriorCode(agent.executionState)` for additional context.

### Token Usage

**Medium–High.** Each exchange costs two LLM calls (responder answer + next-question generation), each with
moderate-length prompts and full-dialogue history growing implicitly via accumulated context. At `max_depth = 5`
this is ~9 LLM calls, plus one final synthesis call over the entire dialogue transcript. Higher `max_depth` values
scale usage linearly.

## Config & Process

### Type Configuration
- `SocraticDialogue` `TaskType`: category `Reasoning`, backed by `SocraticDialogueTaskExecutionConfigData` and generic
  `TaskTypeConfig` (no custom type-level settings).

### Runtime Configuration
- `SocraticDialogueTaskExecutionConfigData` — validated via `ValidatedObject.validate()`:
  - `initial_question` must not be null/blank.
  - `max_depth` must be within `1..20`.
- `maxDescriptionLength = 1500` — internal constant used to truncate Q/A pairs shown in the concise result output.

### Lifecycle

1. **Initialization**
   - Validates `executionConfig` (blank question / out-of-range depth → immediate `CONFIGURATION ERROR` completion).
   - Resolves `related_files` glob patterns via `FileSelectionUtils.filteredWalk`, respecting `.gitignore`-style
     exclusions (`FileSelectionUtils.isIgnored`).
   - Builds combined context from prior task output (`getPriorCode`) and resolved input files.
   - Constructs two `ChatAgent` instances: a *questioner* (temperature 0.7, prompt tuned to challenge/clarify) and a
     *responder* (temperature 0.5, prompt tuned to answer thoroughly and honestly).
   - Opens a transcript file stream and writes the dialogue header.

2. **Execution**
   - Iterates `depth` from `1..maxDepth`:
     - Responder answers the current question (using prior Q&A as context after depth 1).
     - Response is logged to the exchange tab, transcript, full-dialogue buffer, and (for first/last exchange only)
       the concise result buffer.
     - If not at final depth, questioner generates the next probing question based on the response, optionally
       instructed to challenge an assumption (`challenge_assumptions`).
     - Per-exchange timing is recorded and surfaced in both the exchange tab and the Overview tab.
   - After the loop, a synthesis prompt is sent to the responder agent summarizing insights, challenged assumptions,
     contradictions, and further-exploration areas over the full concise dialogue.
   - Final result (concise) is returned via `resultFn`; full dialogue and transcript remain in the UI/file only.

3. **Error Handling**
   - Any exception during the loop is caught: logged, surfaced via `task.error(e)`, appended to the transcript with
     an `❌ Error Occurred` section, and reflected in the Overview tab.
   - `resultFn` is still invoked with a best-effort error payload containing the original question, error message,
     count of completed exchanges, and any partial dialogue accumulated so far — ensuring downstream tasks receive a
     usable (if degraded) result rather than a hard failure.
   - No retry/rollback logic exists; failures are terminal for this task instance but non-fatal to the orchestrator.

## Integration

### Registering in an OrchestrationConfig

```kotlin
val config = OrchestrationConfig(
    // ...existing setup...
)

val socraticTask = SocraticDialogueTask(
    orchestrationConfig = config,
    planTask = SocraticDialogueTask.SocraticDialogueTaskExecutionConfigData(
        initial_question = "Does 'eventual consistency' have a coherent semantics without bounded staleness?",
        related_files = listOf("src/main/kotlin/consensus/*.kt"),
        max_depth = 5,
        challenge_assumptions = true,
        domain_constraints = listOf("distributed systems"),
        task_dependencies = emptyList()
    )
)
```

### Prompt Segments (as injected into agents)

**Questioner agent prompt:**

```text
You are a Socratic questioner. Your role is to ask probing questions that:
1. Challenge assumptions and definitions
2. Explore implications and consequences
3. Identify contradictions or inconsistencies
4. Seek deeper understanding through clarification
5. Guide toward examining fundamental principles

Actively challenge assumptions at each step.

Domain constraints: distributed systems, CAP theorem

Ask one clear, focused question at a time. Build on previous answers to go deeper.
```

**Responder agent prompt:**

```text
You are a thoughtful responder in a Socratic dialogue. Your role is to:
1. Answer questions honestly and thoroughly
2. Acknowledge when you're uncertain
3. Provide clear definitions and reasoning
4. Consider implications of your statements
5. Be open to revising your understanding

Domain constraints: distributed systems, CAP theorem

Provide substantive, well-reasoned responses that advance the dialogue.
```

**Next-question generation prompt (per exchange):**

```text
Previous question: {currentQuestion}

Response received: {currentResponse}

Based on this response, generate the next Socratic question that:
- Challenges an assumption made in the response
- Explores implications or consequences
- Identifies potential contradictions
- Moves toward fundamental principles

Provide only the question, without preamble.
```
